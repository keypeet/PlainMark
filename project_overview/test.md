PRD.md
คือ Product Requirements Document หรือเอกสารหลักของโปรดักต์
จุดประสงค์คือสรุปว่าแอปนี้ทำไปเพื่ออะไร, แก้ปัญหาอะไร, ใครใช้, ฟีเจอร์หลักคืออะไร, อะไรอยู่ใน scope / out of scope, และ success criteria คืออะไร
ไฟล์นี้ควรเป็น “แกนกลาง” ของโปรเจกต์


user-journey.md
คือเอกสารเส้นทางการใช้งานของผู้ใช้
จุดประสงค์คืออธิบายว่าผู้ใช้เริ่มจากตรงไหน ไปทำอะไร กดอะไร เจออะไร และจบด้วยผลลัพธ์อะไร
เช่น เปิดแอป > พิมพ์โน้ต > กดปุ่ม Heading > ดู Preview > Export เป็น .md

user-design.html
คือไฟล์ต้นแบบหน้าตา UI แบบดูได้ใน browser
จุดประสงค์คือทำให้เห็นภาพจริงก่อนเขียนแอป เช่น layout หน้า editor, preview, toolbar ด้านขวา, ปุ่ม export
ไฟล์นี้เหมาะมากสำหรับเช็กว่า “หน้าตาและ flow ใช้ได้ไหม” ก่อนลงมือทำจริง

project_plan.md
คือแผนการทำงาน
จุดประสงค์คือแตกงานออกเป็น phase / milestone / task เช่น MVP ทำอะไรบ้าง, หลัง MVP เพิ่มอะไร, ใช้เวลากี่ช่วง, ลำดับการพัฒนาเป็นยังไง
ไฟล์นี้ช่วยให้ไม่กระโดดไปทำฟีเจอร์ใหญ่ก่อนของหลักยังไม่เสร็จ

architecture.md
อธิบายโครงสร้างระบบคร่าวๆ เช่น frontend, local file handling, markdown rendering, export service, settings
เหมาะมากถ้าจะให้ AI หรือ Dev ทำต่อ เพราะจะเห็นภาพรวมก่อนลงมือ

data-model.md
คือเอกสารโครงสร้างข้อมูล
จุดประสงค์คืออธิบายว่าในแอปจะมีข้อมูลอะไรบ้าง และแต่ละอย่างเก็บอะไร
เช่น Note, File, ExportOption, MarkdownBlock, UserSetting
สำหรับแอปนี้อาจไม่ซับซ้อน แต่ควรมีไว้เพื่อกันออกแบบมั่วตอนเริ่มเขียนโค้ด
